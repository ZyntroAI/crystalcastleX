# 📊 เปรียบเทียบ JSX vs TSX

ทั้งสองคือรูปแบบไฟล์สำหรับเขียนส่วนติดต่อผู้ใช้ (โดยหลักคือ React) — ความแตกต่างหลักคือ**ระบบประเภทข้อมูล (type system)**

## ✅ นิยามพื้นฐาน

### 🔹 JSX (JavaScript XML)

- ไฟล์: `.jsx`
- ส่วนขยายของ JavaScript ธรรมดา
- ช่วยเขียนโครงสร้างคล้าย HTML ในโค้ด JS
- ไม่มีการตรวจสอบประเภทข้อมูล ณ เวลาคอมไพล์

### 🔹 TSX (TypeScript XML)

- ไฟล์: `.tsx`
- ส่วนขยายของ TypeScript
- รวมทุกอย่างของ JSX + ระบบประเภทข้อมูลที่เข้มงวด
- ตรวจสอบความถูกต้องของชนิดข้อมูลก่อนรัน

## ⚖️ ตารางเปรียบเทียบโดยละเอียด

| ด้าน | JSX | TSX |
| --- | --- | --- |
| ภาษาแม่ | JavaScript | TypeScript |
| ตรวจสอบประเภท | ❌ ไม่มี (รันไทม์เท่านั้น) | ✅ มี ณ เวลาคอมไพล์ |
| นามสกุลไฟล์ | `.jsx` / `.js` | `.tsx` (ต้องใช้ `.tsx` เสมอ) |
| การประกาศชนิด | ❌ ไม่รองรับ | ✅ รองรับ `type`, `interface`, `Generic` |
| เครื่องมือ/IDE | พื้นฐาน | ✅ สมบูรณ์: คำแนะนำ, ตรวจข้อผิดพลาด, เปลี่ยนชื่อ |
| ความปลอดภัย | ต่ำ (ข้อผิดพลาดเจอตอนรัน) | สูง (ป้องกันก่อนรัน) |
| การเรียนรู้ | ง่ายกว่า (ไม่ต้องเรียน TS) | ยากขึ้นเล็กน้อย (ต้องเข้าใจ TypeScript) |
| ขนาดคอมไพล์ | เท่ากัน (TSX → JSX) | เท่ากัน (ประเภทถูกลบตอนบิลด์) |
| ความเข้ากันได้ | ทุกโปรเจกต์ React | ต้องตั้งค่า TS/บันเดิล (Vite, Webpack) |
| การนำเข้า | `import Comp from './Comp'` | ต้องระบุประเภท Props/State |

## 📝 ตัวอย่างโค้ดเปรียบเทียบ

### 🔸 JSX (JavaScript)

```jsx
// Component.jsx
function UserCard({ name, age, isActive }) {
  // ไม่มีการตรวจสอบว่า name/age เป็นอะไร
  return (
    <div className="card">
      <h2>{name}</h2>
      <p>อายุ: {age}</p>
      {isActive ? <span>✅ ออนไลน์</span> : <span>❌ ออฟไลน์</span>}
    </div>
  );
}

export default UserCard;
```

ปัญหา: ส่งค่า `age="ยี่สิบ"` หรือ `name={123}` → โค้ดทำงานผิดพลาดตอนรัน

### 🔸 TSX (TypeScript)

```tsx
// Component.tsx
import React from 'react';

// ประกาศโครงสร้าง Props
interface UserCardProps {
  name: string;
  age: number;
  isActive: boolean;
}

// ตรวจสอบทันทีที่เขียน
const UserCard: React.FC<UserCardProps> = ({ name, age, isActive }) => {
  return (
    <div className="card">
      <h2>{name.toUpperCase()}</h2>
      <p>อายุ: {age.toFixed(0)}</p>
      {isActive ? <span>✅ ออนไลน์</span> : <span>❌ ออฟไลน์</span>}
    </div>
  );
};

export default UserCard;
```

ข้อดี: ส่งผิดประเภท → IDE/คอมไพล์แจ้งเตือน **ก่อน** รัน

## 🔄 การคอมไพล์

- **JSX**: ถูกแปลงโดย Babel/SWC → `React.createElement()` → รันในเบราว์เซอร์
- **TSX**: TypeScript ลบส่วนประกาศประเภท → กลายเป็น JSX ธรรมดา → เหมือนกันตอนรัน

→ ไม่มีผลต่อประสิทธิภาพตอนใช้งานจริง

## 🎯 เหมาะกับกรณีใด?

### ✅ ใช้ JSX ถ้า

- โปรเจกต์เล็ก, สคริปต์สั้น, ต้นแบบเร็วๆ
- ทีมไม่มีความรู้ TypeScript
- ต้องการความเรียบง่าย ไม่ต้องการระบบประเภท

### ✅ ใช้ TSX ถ้า

- โปรเจกต์กลาง→ใหญ่, ทีมทำงานร่วมกัน
- ต้องการลดข้อผิดพลาดรันไทม์, บำรุงรักษาง่าย
- ต้องการคำแนะนำอัตโนมัติ, โครงสร้างที่ชัดเจน
- ใช้ไลบรารีสมัยใหม่ (React 18+, Next.js, Remix)

## 🧩 ส่วนขยายที่เกี่ยวข้อง

| นามสกุล | ความหมาย |
| --- | --- |
| `.js` | JavaScript ธรรมดา (ไม่มี JSX) |
| `.ts` | TypeScript ธรรมดา (ห้ามเขียน JSX ในไฟล์ `.ts`) |
| `.jsx` | JSX + JavaScript |
| `.tsx` | JSX + TypeScript (ต้องใช้นามสกุลนี้ถ้ามีแท็ก `<...>`) |

## 📌 สรุปสั้นๆ

- **JSX** = HTML ใน JavaScript
- **TSX** = HTML ใน TypeScript
- TSX มีทุกอย่างของ JSX + ความปลอดภัยของประเภทข้อมูล
- ตอนรันผลลัพธ์เหมือนกัน — ต่างกันแค่ขั้นตอนพัฒนา
