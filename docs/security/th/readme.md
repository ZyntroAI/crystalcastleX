# นโยบายความปลอดภัย (Security Policy)

## เวอร์ชันที่รองรับ (Supported Versions)

เราออกแพตช์ความปลอดภัยเฉพาะสำหรับเวอร์ชันที่ระบุด้านล่างเท่านั้น

| เวอร์ชัน | รองรับ |
| --- | --- |
| main | ✅ |
| < 1.0 | ❌ |

**หมายเหตุ:** โปรเจกต์นี้ยังอยู่ในระยะ Private/Experimental และใช้เพื่อการศึกษาเท่านั้น

## การรายงานช่องโหว่ (Reporting a Vulnerability)

หากคุณพบช่องโหว่ด้านความปลอดภัย **กรุณาอย่าเปิดเป็น Public Issue**

**ช่องทางที่แนะนำในการรายงาน:**
1. เปิดผ่าน [GitHub Security Advisory](../../security/advisories/new) – วิธีนี้ปลอดภัยที่สุด
2. หากเป็นกรณีฉุกเฉินมาก ติดต่อที่: security@yourdomain.com

**สิ่งที่ควรรายงาน:**
- XSS (Cross-Site Scripting)
- SQL Injection
- การรั่วไหลของข้อมูล
- API Key/Token หลุด
- RCE (Remote Code Execution)
- Auth Bypass (การข้ามการยืนยันตัวตน)

**กระบวนการของเรา:**
1. เราจะตอบรับรายงานของคุณภายใน **48 ชั่วโมง**
2. เราจะอัปเดตความคืบหน้าให้คุณทุก ๆ 5 วันทำการ จนกว่าจะแก้ไขเสร็จ
3. เมื่อแก้ไขเสร็จ เราจะให้เครดิตคุณใน Release Notes หากต้องการ

ขอบคุณที่ช่วยทำให้โปรเจกต์นี้ปลอดภัยยิ่งขึ้น

## นโยบายการเปิดเผยข้อมูล (Disclosure Policy)

เรายึดหลักการ *Coordinated Disclosure* ขอให้คุณรอเวลา 90 วันเพื่อให้เราแก้ไขก่อนเปิดเผยต่อสาธารณะ

## ขอบเขตที่ไม่รับรายงาน (Out of Scope)

เราไม่รับรายงานสำหรับปัญหาประเภทต่อไปนี้:
- Rate limiting หรือ DoS ที่ไม่กระทบต่อข้อมูล
- ปัญหาที่ต้องเข้าถึงเครื่องของผู้ใช้โดยตรง (Physical access)
- Social engineering, Phishing
- ช่องโหว่ใน dependency ที่ยังไม่มีแพตช์จากต้นทาง
- Best practice ที่หายไป แต่ยังไม่สามารถ Exploit ได้ เช่น missing header
